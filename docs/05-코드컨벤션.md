# 5. 코드 컨벤션

<aside>
📌

MVP부터 적용하는 코드 규칙입니다. 언어는 TypeScript로 확정. 프로젝트 생성 후 실제 설정 파일(tsconfig, ESLint, Prettier)과 다르면 이 문서를 함께 고칩니다.

</aside>

## 1. 기술 스택 · 라이브러리

| 구분 | 사용 | 비고 |
| --- | --- | --- |
| 언어 | TypeScript (strict) | tsconfig의 strict: true |
| 프레임워크 | electron | 개발 의존성. 타입 정의 포함 |
| 빌드 구성 | electron-vite 계열 템플릿 | main/preload/renderer 빌드가 구성된 템플릿으로 시작. 생성 시점에 최신 상태 확인 (2026-10 기준 electron-vite 5, Electron 44). Electron 44는 설치 시 실행 파일을 자동으로 받지 않아 postinstall의 `install-electron`으로 받는다 |
| 패키징 | electron-builder | Windows 설치 파일 생성 |
| 태그·커버 | music-metadata | 최신 버전은 ESM 전용. import로 불러옴 |
| 로그 | electron-log | 무인 운영 중 문제 추적용 로그 파일 |
| 폴더 감시 | Node.js [fs.watch](http://fs.watch) | Windows에서 문제 발생 시 chokidar로 교체 |
| UI | HTML/CSS/TS (프레임워크 없음) | 탭 4개 규모. 필요해지면 재검토 |
| 포맷·검사 | Prettier, ESLint | 저장 시 자동 포맷 |
| 테스트 (권장) | Vitest | 스케줄러·휴무일 판정 같은 순수 함수 대상. 테스트 파일은 대상 옆에 `*.test.ts` |

날짜 라이브러리는 쓰지 않는다. 시간 비교는 분 단위 정수 변환으로 충분하다.

## 2. 폴더 구조

```
src/
├─ main/       메인 프로세스 (scheduler, day-service, library, settings, system)
├─ preload/    contextBridge로 노출할 API만
├─ renderer/   화면, 재생
└─ shared/     양쪽이 같이 쓰는 타입, IPC 채널 상수, 상수값
```

shared에는 Electron이나 Node.js API를 쓰는 코드를 두지 않는다 (타입과 순수 값만).

## 3. 이름 규칙

| 대상 | 규칙 | 예시 |
| --- | --- | --- |
| 파일명 | kebab-case | day-service.ts |
| 변수·함수 | camelCase, 함수는 동사로 시작 | getNextIndex(), isPlayDay() |
| 클래스·타입·인터페이스 | PascalCase | ScheduleSlot, AppSettings |
| 상수 | UPPER_SNAKE_CASE | TICK_INTERVAL_MS |
| boolean | is/has/should 접두어 | isPlaying, hasSongs |
| IPC 채널 | 영역:동작 | player:play, settings:save |

## 4. TypeScript 규칙

- any 금지. 불가피하면 unknown으로 받고 검사 후 사용한다.
- settings.json처럼 파일에서 읽은 데이터는 그대로 믿지 않고 구조를 검사한 뒤 기본값으로 보완한다. 파일이 깨져도 앱이 멈추지 않아야 한다.
- settings.json에는 version 필드를 두고, 구조가 바뀌면 이전 버전을 변환하는 코드를 추가한다.
- 문자열 리터럴 타입을 활용한다. 예: 재생 상태는 'idle' | 'playing' | 'manual' | 'off-day'

## 5. IPC 규칙

- 채널 이름은 shared/ipc-channels.ts에 상수로 한 번만 정의하고, 문자열을 직접 쓰지 않는다.
- 주고받는 데이터 타입은 shared/types.ts에 정의하고 main·preload·renderer가 같은 타입을 쓴다.
- preload는 window.api 하나만 노출하고, 타입을 선언해 화면에서 자동완성되게 한다. ipcRenderer 자체를 화면에 넘기지 않는다.
- 메인은 화면에서 온 값을 검사한 뒤 사용한다 (예: 드롭된 파일 경로의 확장자).

## 6. 날짜·시간 규칙

<aside>
⚠️

toISOString()으로 날짜를 만들지 않는다. UTC 기준이라 한국 시간 오전 9시 전에는 날짜가 하루 전으로 나온다. 등교 구간(08:30~09:00)에서 바로 버그가 난다.

</aside>

- 날짜 키는 로컬 시간 기준 "YYYY-MM-DD" 문자열. shared의 날짜 함수 하나로만 만든다.
- 시각은 "HH:mm" 문자열로 저장하고, 비교할 때는 자정부터의 분(정수)으로 바꾼다.
- 구간은 시작 포함, 종료 미포함으로 판정한다 (13:00 이상, 14:00 미만).
- 현재 시각(new Date())은 스케줄러 바깥에서 만들어 판정 함수에 인자로 넘긴다. 테스트에서 원하는 시각을 넣을 수 있게 하기 위함.

## 7. 로직 분리

- 재생 여부 판정, 휴무일 판단, 다음 곡 번호 계산은 Electron을 모르는 순수 함수로 만든다.
- Electron API(창, 트레이, IPC)를 부르는 코드는 이 순수 함수를 호출만 한다.
- 공휴일은 공급자 함수(HolidayProvider)를 통해서만 가져온다 (2차 API 대비, 아키텍처 9장).

## 8. 문구 · 에러 · 로그

- 사용자에게 보이는 한국어 문구는 renderer의 messages 파일 하나에 모은다. 화면 코드에 문구를 직접 쓰지 않는다.
- 파일 읽기·쓰기, 재생은 실패할 수 있다고 보고 처리한다. 실패해도 앱 전체가 멈추지 않고 다음 동작으로 넘어간다 (예: 곡 파일 없음 → 다음 곡).
- 사용자에게는 쉬운 문구, 로그에는 기술적 원인을 남긴다.
- 반드시 로그로 남길 것: 앱 시작·종료, 재생 시작·정지(구간명, 곡), 휴무일로 건너뛴 이유, 파일·재생 오류.

## 9. 보안

- contextIsolation, sandbox는 기본값(켜짐)을 유지하고 nodeIntegration은 켜지 않는다.
- preload는 필요한 함수만 노출한다.
- 외부 URL을 로드하지 않는다 (모든 화면은 로컬 파일).

## 10. 포맷

- Prettier: 들여쓰기 2칸, 세미콜론 사용, 작은따옴표, 한 줄 100자, 뒤따르는 쉼표(trailingComma: all) — `.prettierrc.yaml`
- 저장 시 자동 포맷, 커밋 전 ESLint 오류 0개
- 주석은 한국어. “무엇을”보다 “왜”를 적는다 (예: 왜 닫기를 숨기기로 바꿨는지)

## 11. Git

- 브랜치: main(항상 실행 가능한 상태) + feature/기능명 (예: feature/scheduler)
- 커밋: Conventional Commits 형식 + 한국어 설명

| 타입 | 용도 | 예시 |
| --- | --- | --- |
| feat | 기능 추가 | feat: 시간표 저장 기능 추가 |
| fix | 버그 수정 | fix: 오전 9시 전 날짜가 하루 밀리는 문제 수정 |
| refactor | 동작 변경 없는 구조 개선 | refactor: 휴무일 판정을 순수 함수로 분리 |
| style | 화면 디자인·포맷 | style: 재생 화면 블러 배경 적용 |
| docs | 문서 | docs: 설치 체크리스트 추가 |
| test | 테스트 | test: 구간 경계 시각 테스트 추가 |
| chore | 설정·빌드·의존성 | chore: electron-builder Windows 설정 |
