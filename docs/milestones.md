# 개발 단계 (MVP)

각 단계는 이전 단계가 완료 기준을 통과한 뒤 시작한다. 괄호는 요구정의서 번호.

## 1단계. 프로젝트 생성과 곡 하나 재생
- electron-vite 계열 TypeScript 템플릿으로 생성, 폴더를 `src/main|preload|renderer|shared` 구조로 정리
- 루트에 이미 CLAUDE.md·.claude·docs가 있으므로, 템플릿이 빈 폴더를 요구하면 임시 폴더에 만든 뒤 루트로 옮기고 기존 파일은 덮어쓰지 않는다
- package.json 스크립트 이름 맞추기: dev, build:win, typecheck, lint, format, test(`vitest run`)
- ESLint·Prettier·Vitest 설정 (`docs/05-코드컨벤션.md` 포맷 규칙)
- 960×640 창, 보안 기본값 유지, `autoplayPolicy: 'no-user-gesture-required'`
- `src/shared/ipc-channels.ts`, `src/shared/types.ts`, preload의 `window.api` 뼈대
- 버튼으로 테스트 mp3 하나 재생/정지
- **완료 기준:** 맥에서 `npm run dev` → 버튼으로 재생/정지. typecheck·lint·test 통과.

## 2단계. 음악 폴더와 드래그앤드롭 (FR-20~23)
- 음악 폴더 생성·읽기(mp3, wav, ogg, m4a), `fs.watch` 감시, 목록 IPC
- 드롭 → preload `webUtils.getPathForFile` → main에서 확장자 검사 후 복사
- music-metadata로 제목·가수·커버 읽기, 커버 없으면 기본 이미지 (FR-24)
- **완료 기준:** 드롭/탐색기 추가·삭제가 목록에 바로 반영, 음악 아닌 파일은 안내 후 제외.

## 3단계. 시간표와 스케줄러 (FR-01~08, NFR-02)
- settings.json 읽기/쓰기(구조 검사 + 기본값 보완, version 필드), 기본 시간표 3개
- 순수 함수: 구간 안인지 판정, 다음 곡 번호(끝이면 0), 시간표 검증(시작<종료, 겹침)
- 매초 상태 판정 루프, 구간 시작 시 이어서 재생, 종료 시 즉시 정지 + 위치 저장
- 늦게 켜져도 구간 안이면 즉시 재생, 수동 재생 상태 분리
- **테스트 필수:** 08:29:59 / 08:30:00 / 08:59:59 / 09:00:00, 마지막 곡 다음 0번, 겹침 검출
- **완료 기준:** 1~2분짜리 테스트 구간으로 자동 재생·정지·이어서 재생 확인, 앱 재시작 후 위치 유지.

## 4단계. 휴무일 (FR-10~13)
- shared 날짜 유틸(로컬 "YYYY-MM-DD"), `HolidayProvider`(내장 holidays.json)
- 순수 함수 `isPlayDay`: 주말, 공휴일, 사용자 쉬는 날, "오늘은 재생 안 함"
- "오늘은 재생 안 함"은 다음 날 자동 해제
- **테스트 필수:** 토·일, 공휴일, 대체공휴일, 쉬는 날, 08:30에 날짜 키가 오늘인지
- **완료 기준:** 테스트 통과 + 앱에서 오늘을 쉬는 날로 지정하면 재생 안 됨.

## 5단계. 무인 운영 (FR-30~35, NFR-03)
- 트레이 없음. 최소화(–) 상태에서도 재생·스케줄 정상 동작 확인
- X 버튼 → 재생 위치 저장 → 바로 종료 (확인 창 없음)
- 자동 실행, 중복 실행 방지(두 번째 실행 시 기존 창을 앞으로), 새벽 자동 재시작(재생 구간 밖에서만)
- ~~설정 내보내기/가져오기~~ (FR-32 삭제), electron-log 로그(시작·종료·재생·건너뛴 이유·오류)
- **완료 기준:** 최소화한 채로 자동 재생·정지, X로 종료 후 다시 켜면 다음 곡부터 이어짐, 앱을 두 번 실행해도 하나만 동작.

## 6단계. 디자인 적용 (docs/04-화면설계서.md)
- Figma 프레임을 하나씩 가져와 재생 → 시간표 → 노래 → 설정 순서로 구현 (Figma의 "종료 확인 창" 보드는 사용하지 않음)
- Windows 창 버튼 영역: `titleBarStyle: 'hidden'` + `titleBarOverlay`
- **완료 기준:** 각 화면이 Figma와 일치, 문구는 모두 messages.ts.

## 7단계. Windows 빌드와 실제 PC 테스트 (NFR-06)
- electron-builder Windows 설정, 아이콘, 앱 이름
- 실제 PC: 설치, 재부팅 후 자동 실행, 1주일 운영, 로그 확인
- Windows에서 음악 폴더(내 음악)가 OneDrive로 옮겨져 있는지 확인 (앱 시작 로그의 "음악 폴더" 경로로 확인)
- 로그인 자동 실행 시 창이 작업 표시줄에 최소화로 나타나는지, 새벽 03:00 재시작 후에도 최소화로 다시 뜨는지 확인 (로그 "[system] 새벽 재시작")
- 사용 설명서 1장, 설치 체크리스트 → `docs/사용설명서.md`, `docs/설치-체크리스트.md`, 인쇄용 `docs/print/*.pdf`
- 실제 PC 확인 항목은 `docs/실기-테스트-점검표.md` (설치·자동 재생·쉬는 날·무인 운영·1주일 운영표)
- **완료 기준:** PRD 성공 기준 충족.
